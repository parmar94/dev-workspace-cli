# Troubleshooting

## `dws init`

**`.devcontainer already exists (use --force to overwrite)`**
dws won't overwrite an existing setup by default. `--force` replaces `devcontainer.json`, `dws.yaml`, `scripts/` and `agent-policy/`, and keeps any other files.

**`unknown language "…" (available: …)` / `"gh" is a tool, not a language`**
Names come from `dws tools list`. Each name belongs to one kind, so pass it with the matching flag (`--lang`, `--agent` or `--tool`).

**`unknown template "…"`**
See `dws templates list`. Custom templates must sit under `templates:` in the config `dws config path` prints.

**`invalid registry: …`**
Your config's `registry:` section has a problem, and the message lists every one. Common causes:
- an entry with both or neither of `feature`/`script`
- a name with capitals or spaces
- `requires` naming something that doesn't exist or was `removed`

**Prompts don't appear, or look garbled**
- Prompts only appear when stdin and stdout are terminals; piped or CI runs skip them.
- Use `--yes` with flags, or `ACCESSIBLE=1 dws init` for plain line-by-line prompts.

**`Also adding required: node`**
Not an error. An entry you chose (like `codex`) needs another one, so dws added it and installs it first.

## `dws update` and `dws rebuild`

**`no .devcontainer/dws.yaml …; run dws init first`**
`update` needs the `dws.yaml` that `init` writes. For a hand-written dev container, run `dws init --force` once.

**`these generated files were edited by hand since dws wrote them: …`**
dws won't overwrite your edits. Move the change into dws instead: a custom registry entry, `--port`, `--base-image` or a template. Or pass `--force` to discard the edits.

**`Already up to date.`**
Nothing in the selection or generated files would change. Use `dws rebuild` if you just want a fresh container.

**`the devcontainer CLI is not installed`**
`dws rebuild` needs `devcontainer` on PATH, or `npx` to run it. Install it with `npm install -g @devcontainers/cli`, or rebuild from VS Code.

## Building the container

**A feature fails to install**
- Check the reference on [containers.dev/features](https://containers.dev/features) and that the major version tag exists.
- Look at the build log: `devcontainer up --workspace-folder . --log-level debug`.

**A script install fails in `post-create.sh`**
- Scripts run as the container user with `set -euo pipefail`.
- Run one by hand inside the container to see the error: `bash .devcontainer/scripts/<name>.sh`.

**`claude` / `codex` can't save the login, or `~/.claude` is owned by root**
New Docker volumes are owned by root. `post-create.sh` fixes this for setups generated by current dws. For an older setup, regenerate with `--force` and rebuild, or run `sudo chown -R "$(id -u):$(id -g)" ~/.claude ~/.codex` in the container.

## SSH forwarding

**`Error connecting to agent: Permission denied` (macOS)**
Docker Desktop's socket is root-only. Current dws hands it to the container user on every start via `postStartCommand`. For an older setup, regenerate with `--force` and rebuild.

**`The agent has no identities`**
Forwarding works; your host agent is just empty. Run `ssh-add` (or `ssh-add --apple-use-keychain ~/.ssh/id_ed25519`) on the host.

**`Could not open a connection to your authentication agent`**
Check `echo $SSH_AUTH_SOCK` in the container:
- If it's empty, the project wasn't generated with `--ssh-agent`.
- On Linux, the host shell that started the container must have `SSH_AUTH_SOCK` set.

## `dws creds`

**`no running dev container for … ; start it first`**
Start the container (VS Code or `devcontainer up`) and pass the same folder you opened. dws matches it via the `devcontainer.local_folder` label, and resolves symlinks such as `/tmp` → `/private/tmp`.

**`no .devcontainer/dws.yaml in …; pass --user`**
The container wasn't generated by dws. Pass its user, for example `--user vscode` or `--user node`.

**`profile "…" uses long-term access keys`**
dws only passes in temporary credentials. Use an SSO profile or an assume-role profile; see [Credentials](credentials.md#aws-temporary-credentials-from-sso-or-a-role).

**`export credentials for profile …`**
For SSO, your session has expired: run `aws sso login --profile <p>`. Check that the profile name exists in `~/.aws/config` on the host.

**`classic personal access tokens are refused` / `token has no expiry`**
Create a fine-grained token with an expiration date; see [Credentials](credentials.md#github-fine-grained-expiring-tokens).

**`gh is not installed in the container`**
Add it with `dws update --add-tool gh --rebuild`, then pass the token in again.

## Agent guard

**Codex prints `skipped: … already has [shell_environment_policy]`**
You already have that table in `~/.codex/config.toml`. dws won't edit it, so merge the printed `filters` into your table by hand.

**Claude Code refuses to read a file you need**
The rule probably comes from a tool's `guard` or the base set (`.env` files). Either:
- read the file yourself and share only what's needed, or
- regenerate with `--agent-guard=false` (not recommended), or
- override the tool in your registry with a narrower `guard`.

## Claude Code sandbox

**`bwrap: Can't mount proc on /newroot/proc: Operation not permitted`**
`enableWeakerNestedSandbox` is missing. dws sets it, so check that nothing else overrides `sandbox` settings, then regenerate with `dws update --agent-sandbox --yes` and rebuild.

**`/sandbox` shows missing dependencies**
`bubblewrap` and `socat` are installed by `post-create.sh` on Debian/Ubuntu images. On other images, install them yourself.

**A command needs a host that isn't allowed**
Approve it when prompted, or add it to the registry entry with `dws tools add <name> … --domain <host>` and run `dws update --yes`.

**`docker` commands fail under Claude**
Docker can't run inside the sandbox. Run them yourself, or see Claude Code's `excludedCommands`.

## Docs and development

**`docs/reference/… is stale; run make docs`**
A command or flag changed. Run `make docs` and commit the result.
